# Handoff — 세션 인계

세션을 넘길 때, 다음에 이어받는 사람(또는 에이전트)이 **대화 기록을 다시 읽지 않고도** 지금 상태를 파악하고 바로 이어서 일할 수 있도록 저장소 루트의 `.handoff.md`에 기록한다.

## 원칙

- **주장이 아니라 증거.** "됐다"가 아니라 "무엇을 실행했더니 무엇이 나왔다"를 적는다. 파일 경로+줄번호, 실행한 명령과 그 출력, 커밋 해시, 테스트 결과 등 재현/검증 가능한 근거를 남긴다. 근거가 없으면 ✅가 아니라 ⏳나 별도 확인 항목으로 내려간다.
- **실패도 자산이다.** 시도했다가 버린 접근은 이유와 함께 남긴다. 다음 세션이 같은 막다른 길을 다시 걷지 않게 하는 게 목적이다.
- **다음 할 일은 즉시 착수 가능한 단위로.** "리팩토링하기" 같은 막연한 항목이 아니라, 다음 세션이 읽자마자 어디서부터 시작할지 알 수 있는 구체적 단계로 적는다.
- **누적한다.** 이전 `.handoff.md`가 있으면 덮어쓰기 전에 반드시 읽는다. 이전 ❌ 목록은 (해결되지 않았다면) 그대로 이어받고, 이전 ⏳ 중 이번 세션에 처리한 항목은 ✅로 옮긴다. 매번 백지에서 다시 쓰지 않는다.

## 절차

1. **대상 파일 결정.**
   기본값은 저장소 루트의 `.handoff.md`. 사용자가 다른 파일명(`STATE.md` 등)을 지정하면 그것을 쓴다.

2. **기존 기록 읽기.**
   대상 파일이 이미 있으면 전체를 읽고 세 섹션(✅/❌/⏳)의 기존 항목을 파악한다. 없으면 새로 만든다.

3. **현재 상태 수집.**
   대화 내용뿐 아니라 실제 저장소 상태로 교차 검증한다:
   - `git status`, `git diff`, `git log --oneline -10` — 무엇이 바뀌었고 커밋됐는지.
   - 이번 세션에서 실행했던 검증 명령(테스트, 빌드, 린트, 브라우저 확인 등)과 그 결과.
   - TodoWrite 등으로 추적 중인 작업이 있으면 그 상태.
   각 "완료" 후보 항목은 여기서 확인한 사실과 맞아야 ✅로 올라간다. 대화에서는 됐다고 했지만 실제로 파일에 반영되지 않았거나 검증되지 않았다면 ⏳로 내린다.

4. **`.handoff.md` 작성.**
   아래 템플릿을 따른다. 각 섹션은 체크리스트(`- [x]` / `- [ ]`) 형태로 쓴다.

   ```markdown
   # Handoff — <저장소/기능 이름>

   최종 갱신: <YYYY-MM-DD HH:MM, 타임존 or 상대 표현 지양>

   ## ✅ 완료 (증거)
   - [x] <완료된 작업 한 줄 요약>
         근거: <파일:줄 / 실행 명령+출력 요약 / 커밋 해시 / 테스트 결과>
   - [x] ...

   ## ❌ 시도했지만 실패 (반복 방지)
   - [ ] <시도한 접근> — <왜 실패했는지, 어떤 에러/증상이었는지>
   - [ ] ...
   (해당 없으면 "해당 없음"이라고 명시적으로 적는다 — 섹션 자체를 생략하지 않는다)

   ## ⏳ 다음 할 일
   - [ ] <다음 세션이 바로 시작할 수 있는 구체적 단계> (파일/함수/명령 명시)
   - [ ] ...

   ## 참고
   - <다음 세션이 알아야 할 컨텍스트: 왜 이 방식을 택했는지, 미결정 사항, 사용자가 명시한 제약 등>
   ```

5. **저장 후 요약 보고.**
   파일에 쓴 뒤, 사용자에게는 파일 내용을 그대로 다시 나열하지 말고 "무엇을 ✅로 옮겼고, ⏳에 몇 개 남았는지" 한두 문장으로만 알린다.

## 하지 말 것

- 검증하지 않은 항목을 ✅로 적지 않는다.
- 이전 `.handoff.md`의 ❌ 이력을 근거 없이 삭제하지 않는다(해결됐다는 증거가 있을 때만 제거하거나 ✅로 옮긴다).
- `.handoff.md`를 대화 요약문이 아니라 상태 문서로 유지한다 — 시간순 일지가 아니라 "지금 기준 참/거짓"이어야 한다.
